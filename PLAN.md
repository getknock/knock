# Knock

> Prove you're a human with one press of a button on a device you own. Your Wedgie vouches for "wallet address; with humanity".

Status: **M0 done** (`@knock-dev/protocol`, test vectors, icon); **M1 done**: the Knock app runs on the user's Wedgie with its key in `KEY4`, and every request passes on the chip (`tools/knock_check.py`): KNOCK, BECOME with the chip's vouch, BIND, and the computer's QR with Knock's logo in it; Safe Signer's key is untouched. **M2 nearly done**: `KnockBinding` is deployed on World Chain, against World's staging and production verifiers (`contracts/deployments/480.json`), and checked live; what's left is one Simulator proof bound on staging. **M3 in progress**: `knockd` (`server/knockd`) signs World ID requests for `knock-bind` and sends `bind()`, checked live on World Chain. The Console (`apps/door`, `/console`) runs the whole binding: the Wedgie over Web Serial, IDKit's link as a QR on the Wedgie, BIND on the device, `knockd`'s `/bind`. Next: one staging binding with the user's Wedgie and the Simulator (M2's last step), then naming the device in ENS. This file is the living plan. It gets updated whenever the user prompts, gives info, or decisions change. The changelog is at the bottom.

Principle: fun first. Practicality (testnet faucets, airdrops, humans-only pages) is a bonus. Over-engineering is explicitly OK.

## 1. Summary

A Wedgie (Pico + 240x240 LCD + Trust M secure chip) runs the **Knock app**: its own small Wedgie app, built from Safe Signer's parts, with its own key (D12, D17).

- **Setup, once**: bind the device key to a World ID 4.0 nullifier through a stateless `KnockBinding` contract on World Chain (it emits `Bound`). Then name the device in ENSv2 (`wedgie.itzraj.eth`) with `knock.*` records pointing at that binding.
- **A knock**: a dApp opens the **Door** popup → the Wedgie shows the origin + KNOCK → green press → a signed `KnockPass`.
- **Verification**: the site's own verifier checks ENS (active, key), the `Bound` receipt on World Chain, the P-256 signature, the counter, and that the nullifier matches across device, ENS and log.
- Nobody sits in the middle, and Knock's server isn't involved at knock time.

## 3. Design essentials

**Trust model**: one P-256 key, Knock's own: made on the device in Trust M slot `KEY4` (or `KEY3`), never Safe Signer's `KEY2` (D17). Its public key is in the app's save and in ENS (`knock.key`). Three independent authorities:
1. **Identity** = ENSv2 records on the device name.
2. **Humanity** = a `Bound` event on World Chain.
3. **Presence** = the device signs the site's fresh challenge after a physical green press.

Knock never touches funds.

**Wire (Wedgie ↔ Door)**: JSON lines over USB serial, ≤ 6 KB each, `id` echoed. Messages: `knock_hello` → `knock_info`; `knock_qr {n, bits}` → `knock_qr_shown {n, scale, logo}` (draws the computer's QR, no signing; D13); `knock_bind` → `knock_bind_sig` (press); `knock_enroll` → `knock_enrolled` (press; with the chip's vouch, `att`); `knock_confirm` → `knock_confirmed` (stores name, status, nullifier, PoH pointer; drives the badge); `knock_pass` → `knock_pass_sig` (press); `knock_cancel` → `knock_cancelled` (takes a QR down). Errors are `knock_error {error, why}`: the app sends `bad_request, rejected, timeout, not_enrolled, already_enrolled, no_key, too_large`; `busy, cancelled, internal` are reserved. The app keeps answering the firmware's `hello`/`ping` and adds `"knock": 1`, `knock_state` (`ok|none|lost|nochip`), `knock_key`, `knock_qr` (a QR is up) and, until there's a key, `knock_slots`. All of it passes on the chip (M1).

**Device rules**: states IDLE / PROMPT / QR / SIGNING. No signing without a physical green press made after the prompt is fully shown; presses in the first 0.6 s and USB-simulated presses are ignored. Red, 120 s of silence, or `knock_cancel` return to IDLE. The device computes every digest itself from fields it parsed. A monotonic counter is incremented and stored before every `knock_pass` reply. The device has no clock. Screens name the action in words (BECOME, BIND, KNOCK), the device name, and the origin labelled "unverified". Never show button letters.

**Signed structures** (EIP-712, domain `Knock` v`1`): `KnockHello`, `KnockEnroll`, `KnockBind`, `KnockPass(challenge, origin, deviceNode, counter, mode, nullifier, humanRef)`. Signatures are P-256 `r||s`, 64 bytes, low-s, over the digest as given (no re-hash).

**ENS records** on `<label>.<parent>`: `addr` (60), `knock.v=1`, `knock.key` (33-byte compressed P-256), `knock.status` (`active|revoked`), `knock.nullifier`, `knock.poh` (`eip155:480:tx:<hash>`), `knock.sc` (`S1|S2`), optional `knock.att`. The device name sits in a `UserRegistry` subregistry of the parent with a Permissioned Resolver. The device key holds no role.

**`KnockBinding`** (stateless, ownerless, no upgrade path; `contracts/src/KnockBinding.sol`): `bind(nullifier, nonce, expiresAtMin, issuerSchemaId, genesisIssuedAtMin, proof[5], x, y, r, s)`. The device's yes first: its P-256 signature over `KnockBind(block.chainid, this, nullifier, expiresAtMin, K)` (`bindDigest`, a view) via `P256VERIFY` at `0x100`, **s low** (the precompile takes either s). Then the human's: `WorldIDVerifier.verify(...)` with action `keccak256("knock-bind") >> 8`, its RP (`RP_ID`, fixed at deploy) and `signalHash = keccak256(K) >> 8`, where `K` is the 33-byte compressed key (reverts on failure). Then it emits `Bound(nullifier, keyHash, expiresAtMin)` with `keyHash = keccak256(x ‖ y)`. It writes no storage. Anyone may submit it.

**World ID request**: IDKit v4, preset `proofOfHuman`, action `knock-bind`, signal = `0x` + the 66 hex digits of the device's compressed key. `knockd` signs the RP context. The Console shows `connectorURI` on the Wedgie via `knock_qr`.

**Door protocol**: the dApp opens `<door-origin>/knock`; the popup posts `knock/ready`; the dApp posts `knock/request {challenge, mode}`; the Door takes the origin from `event.origin` (never from the message) and checks `event.source`; the result goes back with `knock/result` to that origin only. Modes: **1 Bound** (humanity from the binding) and **2 Fresh** (a World ID proof per knock, `humanRef = keccak256(IDKit result)`).

**Verifier (V1–V8, in order, fail closed)**:
1. Parse (low-s).
2. The challenge is ours, unexpired (≤ 2 min), unconsumed, and the origin is ours.
3. Resolve the name and check validity: not expired, `knock.v`, `status=active` seen ≥ 3 blocks deep, `revoked` honoured from the latest block, cache ≤ 60 s; a key seen revoked is invalid forever.
4. Recompute the `KnockPass` digest from our own challenge and origin; verify the signature under `knock.key`.
5. The counter is above the highest stored for this key.
6. Mode 1: `humanRef` is zero; the signed nullifier equals `knock.nullifier`; the receipt named by `knock.poh` succeeded on an accepted `KnockBinding`, with a `Bound` log whose `keyHash` and `nullifier` match, not expired, final.
7. Mode 2: forward the IDKit result bytes to World's verify API and check `humanRef`, the action, and `signal_hash(challenge)`.
8. Optionally enforce one entry per (site action, nullifier).

Then commit atomically: consume the challenge, store the counter, insert the nullifier. A rejected knock consumes nothing.

**Revocation**: the user's wallet sets `knock.status = revoked` (one mainnet tx). A revoked key never returns; a new device needs a new chip. Binding a new device does not cut off the old one, only revoking does.

## 4. Facts verified (2026-11-05/06)

- **World ID 4.0 on-chain**: `IWorldIDVerifier.verify(uint256 nullifier, uint256 action, uint64 rpId, uint256 nonce, uint256 signalHash, uint64 expiresAtMin, uint64 issuerSchemaId, uint256 credentialGenesisIssuedAtMin, uint256[5] proof) external view`; it reverts on failure, checking in order the Merkle root (`proof[4]`, `InvalidMerkleRoot`), the issuer (`UnregisteredIssuerSchemaId`), the RP's OPRF key, the expiry (`ExpirationTooOld`), then the Groth16 proof (`ProofInvalid`). `action = uint256(keccak256(bytes(action))) >> 8`. Docs recommend an upgradeable proxy for the consumer. `world-id-protocol` `contracts/deployments/core/production.json` lists `worldIDVerifier` proxy `0x…09E00F9F…94d7`, `worldIDRegistry` `0x0000000000aE079e…67d4`, `rpRegistry` `0xD9A213A9…5BbC`. **A proof must be bound within 5 hours**: both verifiers reject an `expiresAtMin` more than 18000 s before the block (`getMinExpirationThreshold`), and Merkle roots age too.
- **ENSv2 mainnet contracts** (docs.ens.domains/learn/deployments): ETH Registry `0xf60aba43…85e2`, Root Registry `0x2553c09b…a91e`, ETH Registrar `0xd6d8369e…cc81`, Universal Resolver V2 `0x06fdd07f…cfd5`, Verifiable Factory `0x77510ba1…30d2`, Permissioned Resolver impl `0x565b0f45…57c5`, User Registry impl `0xfaa23592…8d72`. Sepolia equivalents are on the same page. That page said resolution stays on ENSv1 "until the launch completes"; the user says the launch is done (R1).
- **ENSv2 EAC**: `grantRoles/revokeRoles` per name, `grantRootRoles/revokeRootRoles` contract-wide; `ROLE_REGISTRAR = 1<<0`, `ROLE_RENEW = 1<<16`; fuses are replaced by roles. Subname creation is `register(label, owner, subregistry, resolver, roleBitmap, expiry)` on the parent's `UserRegistry` (deployed through the Verifiable Factory; `initialize` must include `ROLE_REGISTRAR_ADMIN` and `ROLE_RENEW_ADMIN`), then `setSubregistry(parentLabelhash, userRegistry)` on the parent's registry. Permissioned Resolver setters take DNS-encoded names. Never cache token IDs or resolvers (`findTokenId` at write time). Min libs: viem ≥ 2.35.0, ENSjs ≥ 5.2.5 for ENSv2 writes.
- **Wedgie**: Trust M is P-256 only. `c.sign(slot, digest)` signs a digest as given. The factory key's Infineon cert is readable via `c.read(optiga.CERT)`. Apps need `"usb": true` for their own protocol. Saves are readable by any plugged-in computer (public data only). A GitHub-installed app is unsigned with full device access, and any app can use the chip. Web Serial: Chrome/Edge only, one holder of the port at a time.
- **IDKit v4**: the connect URL is exposed as `connectorURI`. Production actions work only with the real World App; staging only with the Simulator. Read in `@worldcoin/idkit-core` 4.6.0's source: the link is `https://world.org/verify?t=wld&i=<request>&k=<key>` (`staging.world.org` for staging; 128 characters, a version-11 code at H); a signal of `0x` and an even number of hex digits goes to World App as those bytes and is hashed as them (`signalBytes`, `hashSignal`), which is what `KnockBinding` hashes; a 4.0 result gives `nullifier` and `proof` as decimal strings, `expires_at_min` and `issuer_schema_id` as numbers (`proof_of_human` = 1, `selfie` 11, `passport` 9303, `mnc` 9310), and the RP's `nonce` at the top. TypeScript 7 no longer loads `@types` packages unasked: name them in `types`.
- **Checked on chain (2026-11-06)**:
  - **ENSv2 is live**: the root registry's `eth` points at the v2 ETH Registry `0xf60a…85e2`. `ur.integration-tests.eth` returns `0x2222…` through both the UR proxy and `0x06fd…cfd5`.
  - **`itzraj.eth`**: not in the v1 registry. In v2 it has resolver `0x5516Dd167987b425942e49541BB0e5cc17CCeBDa`, resolves to `0xdffbfc54c6863e6e5ba271e2f0e15fb5d1efe499`, and has **no subregistry yet**.
  - **World**: both `WorldIDVerifier` proxies have code on chain 480. The relayer (gas key) holds ~0.001 ETH; gas is ~0.0015 gwei.
  - **World Chain for M2**: `P256VERIFY` at `0x100` answers 1 for the vectors' `KnockBind` signature and for its high-s twin (so `KnockBinding` checks low s itself), and nothing for a wrong key. The Knock RP is registered and active in both RP registries; its `rp_…` id is the RP's uint64 in hex. Issuer schema ids 1, 11 and 128 are registered in both environments. Deploying `KnockBinding` took ~476k gas (estimated 619k).
- **Trust M slots** (wedgie.dev/trustm.md): `KEY2` and `DATA[11]` are Safe Signer's. Every other app gets `KEY3`/`KEY4` (empty from the factory), checks the slot isn't locked, and says in its README which it takes. As shipped, any program can use or replace a key in `KEY2`–`KEY4` (`genkey` replaces, no undo); only a lifecycle of 07 locks a slot, for good. Errors carry `optiga.Error.code` (0x07: access rules say no). An empty slot answers a signature with 0x0b, "command out of sequence". That was seen on this Wedgie, and Infineon's table describes it as a command needing a private key the slot lacks (R12). wedgie-dev's `tools/optigaprobe.py` makes test keys in `KEY3`.
- **The user's Wedgie**: firmware 0.3.76, MicroPython 1.29.0, RP2040, OPTIGA Trust M. Runs Safe Signer `safe-59` with its key locked. Sealed. **~74 KB RAM free** at idle.
- **Safe Signer** (`clawdbotatg/wedgie-safe`, upstream `safe-63`):
  - `safe.py` `handle(m)` dispatches on `type`. Rare features are modules imported per request and dropped after (`safe_msg`). Big modules ship as `.mpy`, built by `tools/mpy.sh` (`uv` + `mpy-cross==1.29.0.post2`).
  - Reusable: `sign(digest)` (chip, low-s); `_screen(...)` (question page: ignores presses for 600 ms, times out at 120 s, physical keys only); `W.send`, `W.hello`, `draw_home()`, `save.*`, `safe_keccak.keccak256`.
  - `safe_msg.prove` gives the factory-key signature over `sha256("wedgie safe key\0" + X + Y)` plus the Infineon cert: the future `knock.att`.
- **Dev loop** (wedgie-dev `public/wedgie.py`, served at wedgie.dev/wedgie.py): `hello`, `install .` (installs the app in the current folder through full access; a red question, then a green press), `run file.py`, `debug`. Recovery: hold both grey buttons while plugging in to boot with no app, then reinstall Safe Signer from wedgie.dev/connect.
- **World ID RP signatures** (docs.world.org/world-id/idkit/signatures): the RP's backend signs every request. The message is `0x01`, the nonce (`hash_to_field` of 32 random bytes), `created_at` and `expires_at` (u64, big-endian; World's default TTL is 300 s), then `hash_to_field(action)`: 81 bytes. It's signed EIP-191 (`"\x19Ethereum Signed Message:\n81"`) with secp256k1, as `r‖s‖v`, v = 27 or 28. `hash_to_field(x) = keccak256(x) >> 8`. IDKit takes it as `rp_context {rp_id, nonce, created_at, expires_at, signature}`; the result's top-level `nonce` is the one the proof binds (`verify`'s `nonce`). Checked on chain (2026-11-06): the RP key file's key is the signer `getOprfKeyIdAndSigner` gives for Knock's RP in both World RP registries.

## 7. Risks

- **R1 (resolved 2026-11-06) – ENSv2 live status.** Verified on chain: ENSv2 is live and `itzraj.eth` is in the v2 registry (facts in §4). Both Universal Resolver addresses answer correctly; we use the proxy (D14). The verifier's chain config still supports Sepolia as a fallback.
- **R2 (corrected) – Expiry units.** World's `expires_at_min` / `expiresAtMin` is a **Unix-seconds lower bound**: "min" means minimum, not minutes (World's own example is `1756166400`). The `Bound` expiry check ("zero or later than now") compares seconds with no conversion. Tests should still cover the boundary.
- **R3 (eased by D12) – Built from Safe Signer's parts.** Knock copies a few pieces (the line reader, the screens and their press rules, low-s signing) from upstream `safe-63` instead of tracking a fork, so there's nothing to merge. Fixes upstream, like its press-rule audits, are worth re-reading now and then.
- **R4 – World production vs staging.** Real World App users need a production action. Develop against staging + Simulator. Never accept staging deployments in a production verifier. The IDKit `environment`, the action's environment and Simulator-or-real-app must all match: a staging action with the real World App silently produces no proof (World's SKILL.md). Production is ready (§8); a staging run needs its own `knock-bind` action first.
- **R5 – 36 hours.** The core loop (M1–M5) comes first; see the cut order.
- **R6 – Gas key balance is ~$2.** Fine for staging binds (a fraction of a cent each), but watch it. `knockd` sends only bindings that pass a simulation (D19), at most 12 an hour, which bounds the damage if it leaks.
- **R7 – Honest limits (keep in the README)**: no PIN on the Wedgie (a thief can knock until revoked); proof farming is not solved; the shared public nullifier is linkable across sites in Bound mode; installed apps can use the chip (S1 vs S2); the origin is "unverified" on the device; the Wedgie is not an audited hardware wallet.
- **R8 – Door origin.** Web Serial permission is per origin, and the port is exclusive (the Door and `wedgie.dev/safe` can't run together).
- **R9 – One wallet for controller and revoker** (D9) means a compromised wallet can both rename and revoke, and there's no separate low-power revoke key. Acceptable for now; revisit with a status-only role if time allows.
- **R10 (eased by D12) – Wedgie RAM.** ~74 KB was free at idle under Safe Signer. Knock is much smaller (~29 KB of source across four files), and its request code loads only for a request (`knock_knock`, `knock_key`). `tools/mpy.sh` builds `.mpy` files if RAM gets tight, and the QR is encoded on the computer (D13). Measured on the device: hello's `ram` is ~121 KB free at idle with Knock (versions 2 to 4 alike), against ~73 KB under Safe Signer. Measure again after each new message.
- **R11 (resolved by D17) – A shared Safe key.** Signing Knock messages with Safe Signer's `KEY2` key would have put the user's Safe signer key on chain and in ENS next to `itzraj.eth`, linking the Safe to the name in public, and a bug in a Knock screen could have signed Safe data. Knock has its own key instead, and never names `KEY2`.
- **R12 (resolved 2026-11-06) – An empty slot's answer.** trustm.md doesn't say which error code a signature gets from an empty slot, and Knock's first guess (0x01/0x03/0x05) was wrong. On the user's Wedgie both empty slots answered 0x0b ("command out of sequence"), so Knock made nothing and showed `error 0x0b` in `knock_slots`. Infineon's error table describes 0x0b as a command needing a private key the slot doesn't have. The user chose 0x0b as the only "empty" answer: any other answer, the old guesses included, leaves a slot alone.
